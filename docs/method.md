# 口径与执行规则

## 时点语义

以信号日 T 在交易日历中的序号为基准：

```
买入日 = T + entry_offset          默认 entry_offset = 1
卖出日 = 买入日 + hold_days         默认 hold_days = 1 → T+2
```

`hold_days=H` 的含义是**买入日到卖出日之间正好跨 H 个交易日**。默认口径
（H=1、开盘买、收盘卖）即：T 日收盘后出信号 → T+1 开盘买 → T+2 收盘卖，
槽位数自动推导为 H+1 = 2。

`entry_offset` 强制 ≥1。T 日信号在 T 日成交属于前视，构造 `ExecConfig` 时直接报错。

买入价与卖出价各自可选：

| 取值 | 复权列 | 说明 |
|---|---|---|
| `open` | `adj_open` | 开盘集合竞价 |
| `close` | `adj_close` | 收盘集合竞价 |
| `vwap` | `adj_vwap` | 全天成交量加权均价 |

成交与损益一律用**复权价**；涨跌停判断用**原始价**（涨跌停价本身是原始价口径）。
估值用 ffill 后的复权收盘价——停牌日沿用最近有效价，成交价则从不 ffill。

## 执行规则

与 HistQuantOpt 的 `RealisticBacktester` / `ExecutionLedger` 同口径，两边净值可比。

| 情形 | 处理 |
|---|---|
| 买入日成交价涨停（`raw ≥ limit_up × 99.9%`） | 放弃该票，资金留在现金 |
| 买入日停牌（`trade_status == "停牌"`） | 放弃该票 |
| 买入日无行情（未上市 / 已退市 / 代码错误） | 放弃该票，计入 `no_quote` |
| 卖出日成交价跌停（`raw ≤ limit_down × 100.1%`） | 顺延到下一可交易日，`side=sell_deferred` |
| 卖出日停牌 | 顺延 |
| 退市（面板中该票整行消失，价格与 `trade_status` 同时缺失） | 不论是否到期，当日按最近有效收盘价强制核销、扣卖出费，`side=sell_delist` |
| 费率 | 非对称：买入 `cost_buy` 默认 1‰，卖出 `cost_sell` 默认 2‰（含印花税） |

**停牌不等于退市**：停牌日面板中仍有该票的行（`trade_status="停牌"`），走顺延；
只有价格与交易状态**同时**缺失才判定退市。这条区分由
`tests/test_execution_rules.py::test_suspension_is_not_treated_as_delisting` 守住。

`trade_status` 共 5 种取值（交易 / 停牌 / XD / XR / N），其中 XD（除息）、XR（除权）、
N（新股首日）都可正常交易，因此不可成交的判定只写 `== "停牌"`，绝不写 `!= "交易"`。

## 资金模式

`--capital-mode` 有两种，**默认 slots**。

### slots（默认）：可用现金按剩余空槽均摊

```
budget = 可用现金 / (N − 已占用槽数)
```

一次建仓占一个槽，持仓卖光后释放。这一条式子自动覆盖了几种情形：

- **全部空仓**时 k=0 → `现金/N`，天然等分，不需要额外的重置逻辑；
- **只剩一个空槽**时 → 现金全投，赚到的钱当轮就滚进去，不留余额；
- **某只票卡住**（停牌/跌停卖不出）时该槽持续占用，但**现金不被锁死**，
  剩余资金照样均摊到其余空槽；
- **先买后卖**的口径下，当日到期尚未卖出的桶仍占着槽，分母自然少一个，
  「回款在途」不必单独建模。

槽位全被占满时跳过当日信号（计入 `no_free_slot_days`），不超配。

### N 与 H 解耦

**H 决定持有多久，N 决定单次下多重。** 每天建一仓时，稳态占用槽数约为 H+1
（先卖后买口径为 H），资金利用率的**上限**为 `(H+1)/N`；实测约为该上限的
七成，差额来自买入失败（涨停买不进）与卖出回款的周转间隙。

#### N 的下限由卡仓决定

槽位被卖不掉的股票占满时，当日信号直接丢弃（`no_free_slot_days`），
此时**实际仓位不可控**，不同 N 之间连仓位都不可比。所需 N 取决于每天选几只——
选股越多、越容易踩到跌停，需要的槽位越多：

| 信号 | 每天选股数 | 卡仓消失所需 N |
|---|---|---|
| 涨停 | 70 只 | **N ≥ 9** |
| 随机基线 | 10 只 | **N ≥ 5** |

**取刚好不卡仓的最小 N**，让信号完整执行。

#### 扫 N 不能用来挑策略

2024-01-01 ~ 2025-12-31、H=2、开盘买收盘卖，同一份信号只变 N：

| N | 涨停利用率 | 涨停年化 | 随机利用率 | 随机年化 |
|---|---|---|---|---|
| 3 | 50.3% | -58.5% | 65.2% | -4.54% |
| 4 | **53.3%** | -60.5% | 50.9% | -2.06% |
| 6 | 45.8% | -58.5% | 33.8% | -1.30% |
| 9 | 26.9% | -38.7% | 22.4% | -0.49% |
| 10 | 23.4% | -34.4% | 20.1% | -0.36% |
| 15 | 14.2% | -21.9% | 13.4% | -0.08% |
| 20 | 10.2% | -16.1% | 10.0% | **0.00%** |

两列年化都随 N 单调向零收敛，**连纯随机选股也不例外**——N=20 时随机基线的
年化精确归零，因为仓位趋近于零，不交易就不亏。涨停策略的 -58% → -16% 是
同一个机制，不是策略变好了。

所以：**跨 N 比较策略优劣无效，比的是仓位。要比策略，两次回测的 N 必须相同。**
也不要靠加大 N 来"控制风险"——低仓位会让净值曲线虚假地变稳。

注意利用率在小 N 区间**不单调**：涨停策略 N=4 的 53.3% 高于 N=3 的 50.3%，
因为 N=3 槽太少，跳过建仓反而浪费了资金。峰值之后才单调下降。

扫描脚本产物见 `output/scan_n_limitup.csv` / `output/scan_n_random.csv`。

### shared：共享现金池

每日预算 = `min(前收盘总资产 / 桶数, 可用现金)`。预算基准是**昨收总资产**
（滞后一天），上涨行情里当日现金会高于该基准，于是买不满、留下余额；
slots 直接按当前现金均摊、投满。这是定义差异，不是执行失败。

保留 shared 主要为了与 HistQuantOpt 的 `rotate` 口径对齐比较。

## 停牌与卡仓

停牌卖不出时钱确实回不来，这是真实约束，回测能选的只是**怎么记账**：

- **默认（`--writeoff-stuck-days 0`）：无限顺延。** 复牌首日可交易就卖，
  期间该槽一直占用，估值沿用 ffill 的最近有效价。最贴近现实。
- **可选：超时强制核销。** `--writeoff-stuck-days N` 表示卖出受阻超过 N 个
  交易日后，按最近有效价强制出局、释放槽位，成交记为 `sell_writeoff`。
  **这是假设不是现实**——钱并没有真的回来，只用于回答「如果不是那几只卡住的
  股票，策略表现如何」，不要拿它当默认口径出结论。

两个监控指标：`avg_frozen_pct` / `max_frozen_pct` = 已过到期日却仍未卖出的
持仓市值占净值比例。这个数字大到一定程度，净值本身就不可信了。

实测量级（涨停信号，2024-2025，日均 70 只）：冻结市值平均 **0.3%**、
最高 5.9%；开 20 天核销阈值只触发 4 笔，年化从 -34.4% 变成 -33.1%。
**停牌不是这类策略的主要矛盾**——卖出受阻里跌停 1933 笔·天、停牌仅 327 笔·天。
真正决定结果的是 N 的选择和涨停买不进的比例。

## 资金分桶与资金利用率

默认槽数 N（= H+1 或 H，见上）的推导规则对 slots / shared 两种资金模式相同，下面补充推导细节与 shared 模式的具体数值示例；slots 模式下同样的闲置还要叠加卡仓因素（见上「N 的下限由卡仓决定」）。

每日建仓预算 = `前收盘总资产 / 桶数`，桶内逐票等权。

### 桶数为什么不等于 H

一笔钱从买入时点占用到卖出时点。若**卖出时点晚于买入时点**（如开盘买、收盘卖），
卖出当日的回款赶不上当日开盘的建仓，这笔钱要跨 **H+1** 个建仓时点，
所以桶数自动取 H+1；只有当卖出时点不晚于买入时点（开盘买+开盘卖、收盘买+收盘卖）
时，回款当日即可复用，桶数才等于 H。

强行按 1/H 分桶（`n_buckets=H`）会在启动阶段错位一次，之后永久欠一桶资金，
退化成周期性的**建仓不足**——桶照建，但金额远低于目标。这比彻底跳过更隐蔽，
所以 `exec_stats` 单独报 `underfunded_buy_days` 与 `avg_funding_gap`。

### 结构性现金闲置

改桶数**不会**降低平均现金占比。开盘买、收盘卖的口径下，永远有一桶回款在途，
现金占比的物理下限就是 `1/(H+1)`，`exec_stats.structural_cash_pct` 直接报这个值。
H+1 换来的是每日预算稳定、不出现「跳过一天 → 次日现金翻倍」的震荡。

要真正吃掉这部分闲置，只能把卖出时点提前到不晚于买入时点：

| 口径（H=2） | 桶数 | 结构闲置 | 实测平均现金占比 |
|---|---|---|---|
| T+1 开盘买、T+3 收盘卖 | 3 | 1/3 | 38.9% |
| T+1 开盘买、T+3 开盘卖 | 2 | 0 | 9.8% |

（实测值取 2024-01-01 ~ 2025-12-31 的涨停信号样本，日均 70 只。）

`vwap` 是全天均价、不对应单一时点，无法保证卖在买前，一律保守地按「先买后卖」处理。

## 前视自查

- 信号日 T 的选股只能用 ≤T 的数据；成交日 ≥ T+1 由 `entry_offset ≥ 1` 强制。
- 内置信号生成器（`limit-up` / `random`）只读 T 日截面，不含未来信息。
- 引擎逐日推进，第 i 日只访问 `frames` 的第 i 行及更早行；退市核销用的
  「最近有效价」来自 ffill 后的历史价，不含未来价。
- 自有信号接入前，建议用 `look-ahead-detector` 复核构建代码。

## 随机基线

`hqpick signal random` 在同一套执行口径下生成随机选股。任何策略的净值都必须
显著跑赢它，否则「超额」只是执行规则或市场 beta 带来的假象。用法见操作指南。
