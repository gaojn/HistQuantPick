# 操作指南（新成员必读）

## 0. 环境

```bash
pip install -e .
```

行情缓存与 HistQuantOpt 共用，默认 `~/quant_data/ashare_cache/`，
里面是 `ashare_daily_<year>.parquet`。换目录：

```bash
export HQPICK_CACHE=/path/to/ashare_cache
```

缓存的生成/更新走 HistQuantOpt 的 `scripts/sync_ashare_cache.py`，本包只读不写。

自检：

```bash
python3 -m pytest -q
```

## 1. 准备选股列表

选股列表是本包唯一的策略输入：`[date, code]` 长表（parquet 或 csv），
`date` 是**信号日 T**（T 日收盘后可知的信息），每日只数不限、可为 0。
多余的列会被忽略。

### 内置信号

T 日涨停的股票：

```bash
python3 -m hqpick signal limit-up --start 2024-01-01 --end 2025-12-31 --out output/picks_limitup.parquet
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--min-list-days` | 120 | 最少上市天数，剔次新股 |
| `--include-st` | 关 | 加上则不剔除 ST（ST 涨跌停幅度不同，默认剔除） |
| `--min-amount` | 0 | 当日最低成交额（元） |
| `--max-per-day` | 不限 | 每日最多保留几只，按成交额降序取 |

随机基线（判断超额是否只是执行规则或 beta 的假象）：

```bash
python3 -m hqpick signal random --start 2024-01-01 --end 2025-12-31 --n 10 --seed 42 --out output/picks_random.parquet
```

### 自有策略

直接产出 `[date, code]` 长表即可。命名遵循全局规范
`日期(YYYYMMDD)_策略名_版本号`，例如 `20260817_limitup_v1.parquet`。

## 2. 回测

```bash
python3 -m hqpick run --picks output/picks_limitup.parquet --hold-days 2 \
    --start 2024-01-01 --end 2025-12-31
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--hold-days` | 2 | 持有期 H：买入日后再跨 H 个交易日卖出 |
| `--entry-offset` | 1 | 信号日到买入日的偏移，须 ≥1 |
| `--entry-price` | open | 买入价 open / close / vwap |
| `--exit-price` | close | 卖出价 open / close / vwap |
| `--capital-mode` | isolated | `isolated`=各份独立滚动、用满不留余、空仓重新等分；`shared`=共享现金池 |
| `--n-buckets` | 自动 | 资金分桶数（isolated 下即份额数），默认按资金周转推导（开盘买/收盘卖为 H+1） |
| `--cost-buy` | 0.001 | 买入费率 |
| `--cost-sell` | 0.002 | 卖出费率 |
| `--initial-value` | 1e8 | 初始资金（元） |
| `--risk-free` | 0.02 | 年化无风险利率（Sharpe 用） |
| `--out-dir` | `output/<口径标签>` | 产物目录 |

口径标签形如 `T+1open_hold2_T+3close_b3i`，含买入偏移、持有期、卖出时点、桶数与资金模式（`i`=isolated / `s`=shared），
不同口径的产物自然分目录，不会互相覆盖。

## 3. 读产物

`output/<口径标签>/`：`nav.csv`、`trades.csv`、`metrics.json`、`exec_stats.json`、
`picks.parquet`（本次用的选股快照）。

`trades.csv` 的 `side` 列区分四种成交：

| side | 含义 |
|---|---|
| `buy` | 正常建仓 |
| `sell` | 到期正常卖出 |
| `sell_deferred` | 因跌停/停牌顺延后卖出 |
| `sell_delist` | 退市强制核销 |

### exec_stats 怎么看

先看这几个字段判断回测是否可信：

| 字段 | 含义与阈值 |
|---|---|
| `buy_fail_breakdown.limit_up` | 因 T+1 涨停买不进的笔数。追涨类策略这项很大是正常的，但它意味着实际成交的样本与信号样本有系统性偏差 |
| `sell_defer_breakdown` | 跌停/停牌导致的顺延笔数（按票·天计） |
| `delist_forced_count` | 退市核销笔数 |
| `no_free_sleeve_days` | **isolated 关键指标**：所有份额都占着仓、当日信号被跳过的天数。占比高说明大量资金被卡仓锁死，净值的低波动其实是低仓位造成的 |
| `sleeve_reset_count` | 全部空仓触发重新等分的次数 |
| `underfunded_buy_days` / `avg_funding_gap` | shared 模式的建仓不足天数与平均缺口。默认桶数下应为 0；不为 0 说明现金被卖不出的持仓卡住 |
| `structural_cash_pct` | 该口径下现金闲置的理论下限，见 [method.md](method.md#资金分桶与资金利用率) |
| `avg_cash_pct` | 实际平均现金占比。显著高于 `structural_cash_pct` 说明大量买入失败 |
| `delisted_stuck_count` / `stale_value_pct` | 末日靠陈旧价估值的滞留持仓，占比大则净值不可信 |
| `unexecutable_signal_days` | 因买入日超出区间而未执行的信号日 |

## 4. 对照实验

同一份选股、扫不同口径，逐个比：

```bash
for h in 1 2 3 5 10; do python3 -m hqpick run --picks output/picks_limitup.parquet --hold-days $h --start 2024-01-01 --end 2025-12-31; done
```

结论前必做的对照：**同口径跑一遍随机基线**。策略净值跑不赢随机基线，就没有 alpha。

## 5. 已知边界（阶段 1）

当前版本只到净值与逐笔账本，以下尚未实现：

- 逐笔归因报告（胜率/赔率/持有期收益分布/行业切片）与 HTML 报告
- 参数网格扫描的汇总对比表
- 桶内非等权（按打分/市值加权）——`picks` 的 `weight` 列尚未消费
- 指数基准（当前基准固定为全市场等权 `equal_weight`）
- 涨停买不进的替代策略（顺延买入 / 摊到其他票），当前只有「放弃」
