# 操作指南（新成员必读）

## 0. 环境

```bash
pip install -e .
```

行情缓存与 HistQuantOpt 共用，默认 `~/quant_data/ashare_cache/`，
里面是 `ashare_daily_<year>.parquet`。换目录：

```bash
export HQPICK_CACHE=/path/to/ashare_cache
```

缓存的生成/更新走 HistQuantOpt 的 `scripts/sync_ashare_cache.py`，本包只读不写。

自检：

```bash
python3 -m pytest -q
```

## 1. 准备选股列表

选股列表是本包唯一的策略输入：`[date, code]` 长表（parquet 或 csv），
`date` 是**信号日 T**（T 日收盘后可知的信息），每日只数不限、可为 0。
多余的列会被忽略，重复行自动去重。

**date 支持的形式**（同一列里混用也可以）：

| 形式 | 示例 |
|---|---|
| datetime / date / Timestamp | `datetime.date(2024, 1, 2)` |
| ISO 字符串 | `"2024-01-02"`、`"2024/01/02"` |
| 紧凑字符串 | `"20240102"` |
| **整数 / 浮点** | `20240102`、`20240102.0` |

数值型一律按 YYYYMMDD 解释。注意 pandas 默认会把 `20240102` 当成 Unix
纳秒时间戳读成 1970 年，本包已专门处理——但如果你在传入前自己调过
`pd.to_datetime`，请确认结果是 2024 年而不是 1970 年。

**code 必须带交易所后缀**：`600000.SH` / `000001.SZ`，与行情缓存一致。
传 `600000` 或 `"600000"` 会在回测入口直接报错（早期版本会静默跑出一条
恒为 1 的净值曲线）。部分代码对不上是允许的（退市、区间外），只在超过一半
对不上时打 warning。

### 内置信号

**下影线放量**（每日打分取前 N）：

```bash
python3 -m hqpick signal lower-shadow --start 2024-01-01 --end 2025-12-31 --n 5 --out output/picks.parquet
```

口径：下影线比率 = (min(开,收) − 最低) / 昨收；放量倍数 = 当日量 / 过去 N 日均量
（右对齐到 T−1、不含当日）。两项各取当日截面百分位、等权相加取前 N。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--n` | 10 | 每日选股数 |
| `--volume-window` | 20 | 均量窗口 |
| `--min-shadow` | 0.02 | 最小下影线比率 |
| `--min-volume-ratio` | 1.0 | 最小放量倍数 |
| `--min-float-mv` | 0 | 最低流通市值（**亿元**） |
| `--min-amount` | 5e4 | 最低成交额（**千元**，见下方单位说明） |

**涨停 / 连续涨停**：

```bash
python3 -m hqpick signal limit-up --consecutive 2 --start 2017-01-01 --end 2026-07-16 --out output/picks.parquet
```

`--consecutive 2` 即「连续两天涨停」，配默认口径就是「第 1、2 天涨停 → 第 3 天开盘买
→ 第 4 天收盘卖」。停牌日不算涨停、会打断连续。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--consecutive` | 1 | 要求连续几天涨停（含当日） |
| `--min-list-days` | 120 | 最少上市天数，剔次新股 |
| `--include-st` | 关 | 加上则不剔除 ST |
| `--min-amount` | 0 | 最低成交额（**千元**） |
| `--max-per-day` | 不限 | 每日最多保留几只（按成交额降序） |

**随机基线**（判断超额是否只是执行规则或 beta 的假象）：

```bash
python3 -m hqpick signal random --start 2024-01-01 --end 2025-12-31 --n 10 --seed 42 --out output/picks.parquet
```

> **缓存字段单位**（易踩坑）：价格是元，`volume` 是**手**，`amount` 是**千元**，
> `float_mv` / `total_mv` 是**万元**。所以「成交额 ≥ 5000 万元」要写 `--min-amount 5e4`。
> 详见 `hqpick/data/panel.py` 头部的单位表。

### 自有策略

直接产出 `[date, code]` 长表即可。命名遵循全局规范
`日期(YYYYMMDD)_策略名_版本号`，例如 `20260817_limitup_v1.parquet`。

## 2. 回测

```bash
python3 -m hqpick run --picks output/picks_limitup.parquet --start 2024-01-01 --end 2025-12-31
```

默认口径是 **T+1 开盘买 → T+2 收盘卖、槽位 2**（H=1 时 N 自动推导为 H+1=2）。

| 参数 | 默认 | 说明 |
|---|---|---|
| `--hold-days` | 1 | 持有期 H：买入日后再跨 H 个交易日卖出（默认 T+1 买、T+2 卖） |
| `--entry-offset` | 1 | 信号日到买入日的偏移，须 ≥1 |
| `--entry-price` | open | 买入价 open / close / vwap |
| `--exit-price` | close | 卖出价 open / close / vwap |
| `--capital-mode` | slots | `slots`=可用现金按剩余空槽均摊 `现金/(N−占用槽数)`；`shared`=共享现金池 |
| `--n-buckets` | 自动 | 槽位数 N，决定单次仓位（≈1/N）。默认按 H 推导；设大可留卡仓缓冲，代价是现金闲置，见 [method.md](method.md#n-与-h-解耦) |
| `--writeoff-stuck-days` | 0 | >0 时卖出受阻超期按最近有效价强制核销（**假设口径**，钱并未真回笼，仅供敏感性分析）；0=无限顺延 |
| `--cost-buy` | 0.001 | 买入费率 |
| `--cost-sell` | 0.002 | 卖出费率 |
| `--initial-value` | 1e8 | 初始资金（元） |
| `--risk-free` | 0.02 | 年化无风险利率（Sharpe 用） |
| `--out-dir` | `output/<口径标签>` | 产物目录 |

口径标签形如 `T+1open_hold1_T+2close_b2slots`，含买入偏移、持有期、卖出时点、槽数与资金模式，
不同口径的产物自然分目录，不会互相覆盖。

## 3. 读产物

`output/<口径标签>/`：

| 文件 | 内容 |
|---|---|
| `report.html` | **自包含 HTML 报告**（净值/执行质量/逐笔归因），无外部依赖，可直接发人 |
| `nav.csv` | 净值与日收益 |
| `trades.csv` | 成交流水（一行一次买/卖） |
| `round_trips.csv` | 逐笔完整交易（买卖已配对，含单笔净收益、持有期、卖出方式） |
| `metrics.json` | 净值层指标 |
| `exec_stats.json` | 执行统计 |
| `picks.parquet` | 本次用的选股快照 |

`--no-report` 跳过 HTML 生成，`--title` 自定义报告标题。

`trades.csv` 的 `side` 列区分四种成交：

| side | 含义 |
|---|---|
| `buy` | 正常建仓 |
| `sell` | 到期正常卖出 |
| `sell_deferred` | 因跌停/停牌顺延后卖出 |
| `sell_delist` | 退市强制核销 |
| `sell_writeoff` | 卡仓超时强制核销（仅当 `--writeoff-stuck-days > 0`，属假设口径） |

### exec_stats 怎么看

先看这几个字段判断回测是否可信：

| 字段 | 含义与阈值 |
|---|---|
| `buy_fail_breakdown.limit_up` | 因 T+1 涨停买不进的笔数。追涨类策略这项很大是正常的，但它意味着实际成交的样本与信号样本有系统性偏差 |
| `sell_defer_breakdown` | 跌停/停牌导致的顺延笔数（按票·天计） |
| `delist_forced_count` | 退市核销笔数 |
| `no_free_slot_days` | **首要指标**：槽位全被占满、当日信号被跳过的天数。数值大说明 N 偏小（默认 H+1 在多票策略下常常不够），净值的低波动其实是低仓位造成的 |
| `avg_frozen_pct` / `max_frozen_pct` | 已过到期日仍未卖出的持仓市值占净值比。大到一定程度净值不可信 |
| `writeoff_forced_count` | 卡仓超时强制核销笔数（>0 说明结论建立在假设口径上） |
| `underfunded_buy_days` / `avg_funding_gap` | shared 模式的建仓不足天数与平均缺口 |
| `structural_cash_pct` | 该口径下现金闲置的理论下限，见 [method.md](method.md#资金分桶与资金利用率) |
| `avg_cash_pct` | 实际平均现金占比。显著高于 `structural_cash_pct` 说明大量买入失败 |
| `delisted_stuck_count` / `stale_value_pct` | 末日靠陈旧价估值的滞留持仓，占比大则净值不可信 |
| `unexecutable_signal_days` | 因买入日超出区间而未执行的信号日 |

## 4. 参数网格扫描（hqpick grid）

同一份选股、同一份行情，只变执行口径；行情只加载一次，比手写 for 循环快得多。

```bash
python3 -m hqpick grid --picks output/picks_limitup.parquet --start 2024-01-01 --end 2025-12-31 \
    --hold-days 1,2,5 --n-buckets 5,10 --baseline
```

各轴都接受逗号分隔的多值，笛卡尔积展开：`--hold-days` / `--n-buckets` /
`--entry-price` / `--exit-price` / `--capital-mode` / `--writeoff-stuck-days`。
产出汇总 csv（默认 `output/grid_summary.csv`）并在终端打印对比表。

**`--baseline` 是关键**：它按策略的日均选股数生成随机选股，用**完全相同的口径**
再跑一遍。只有这样才能把「选股能力」和「仓位/口径带来的收益」分开。实测例子：

| H | 策略年化 | 同口径基线 | 差距 |
|---|---|---|---|
| 1 | -23.7% | -0.4% | -23.3 |
| 2 | -34.4% | +2.8% | -37.2 |
| 5 | -51.6% | +11.0% | -62.6 |

单看策略列会以为 H=1 相对好，其实那只是仓位低（利用率 11.7%）；对照基线后
才看出真实结论是持有期越长、相对基线越差。

**N 怎么取**：取刚好让 `no_free_slot_days` 归零的最小 N（涨停这类日均 70 只的策略约 9~10，
日均 10 只的约 5~6）。再往上加只是降仓位——扫 N 会让年化单调向零收敛，
**连纯随机选股也一样**，所以扫 N 不能用来挑策略，见 [method.md](method.md#扫-n-不能用来挑策略)。

比较任意两个配置前，先核对 `无空槽跳过天数` 与 `资金利用率`——否则比的是仓位不是选股。

## 5. 分年与分月

报告的「分年与分月」一节有三块：

| 块 | 回答的问题 |
|---|---|
| 分年表现 | 每年的收益/基准/超额/波动/回撤/Sharpe，以及**按买入年份归属**的交易笔数、逐笔胜率、平均单笔 |
| 月度收益矩阵 | 行=年、列=1~12月的月收益（按数值上色），外加「全年」与「全年超额」列 |
| 月份效应 | 每个自然月份跨年汇总的平均收益与为正比例 |

月度矩阵是用来看**收益是否集中**的。涨停信号实测：24 个月里只有 3 个月正收益，
其中 2024 年 10 月 +18.6%（普涨月）——正收益高度依赖一次行情而非持续 edge。

分年表的逐笔胜率还能判断 edge 是否稳定：涨停信号 2024 年 42.3%、2025 年 41.9%，
两年几乎一致，说明负 alpha 是稳定特征而非某年偶然。

月份效应那张表的样本量很小（每个月份只有 N 年），**不能据此下季节性结论**。

## 6. 逐笔归因怎么看

净值层指标受仓位和资金利用率影响，逐笔统计不受——**两者要一起看**。
报告的「逐笔归因」一节给出：

| 指标 | 含义 |
|---|---|
| 胜率 | 盈利笔数占比 |
| 平均盈利 / 平均亏损 | 分别在盈利笔与亏损笔上的均值 |
| 盈亏比 | 平均盈利 / \|平均亏损\|。>1 表示赢的时候赚得更多 |
| 期望值 | 胜率×平均盈利 + 败率×平均亏损，逐笔口径的 edge |
| 分位分布 | 最差/5%/25%/中位/75%/95%/最好 |
| 按卖出方式 | 正常到期 / 顺延卖出 / 退市核销 / 卡仓核销 各自的胜率与盈亏 |
| 按买入月份 | edge 是稳定的还是只靠某几个月 |

**盈亏平衡胜率** = 平均亏损 / (平均盈利 + 平均亏损)。把它和实际胜率比，才知道策略是「赢得不够多」还是「赢的次数不够」。涨停信号实测：盈亏比 1.10、平衡胜率 47.5%，实际胜率仅 39.6%——病因是赢的次数太少，这一点净值曲线看不出来。

## 7. 交易分布（行业 / 市值）

报告的「交易分布」一节按**买入日截面**给出所交易股票的构成：

- **流通市值**：分位卡片 + 六档分布（<30亿 / 30-50 / 50-100 / 100-300 / 300-1000 / ≥1000亿），
  每档的笔数占比、资金占比、逐笔胜率、平均单笔、合计盈亏
- **行业**：中信一级行业（前 15 个，其余并入「其他」），同样的指标

用途是判断策略实际押在什么标的上。下影线信号实测：中位市值仅 35.6 亿、
42.5% 的交易落在 <30 亿的微盘股，且**市值越小亏得越多**（<30亿 平均单笔 -1.27%，
100-300亿 -0.05%）——这类诊断净值曲线给不出来。

## 8. 已知边界

- 桶内非等权（按打分/市值加权）——`picks` 的 `weight` 列尚未消费
- 指数基准（当前基准固定为全市场等权 `equal_weight`）
- 涨停买不进的替代策略（挂涨停价撮合 / 顺延买入），当前只有「放弃」。
  这对打板类策略影响很大：连续 2 板信号有 25% 因 T+1 一字板买不进，
  买到的都是没封住的弱票，构成系统性逆向选择
- `hqpick/signals/reversal.py`（短期反转族因子）已实现并有完整测试覆盖，但**未接入 CLI**——该族因子全部候选在验证中被证伪（见
  [实验记录.md](实验记录.md)），暂不作为一等公民暴露，避免团队成员误当成推荐信号使用；因子计算逻辑保留供后续研究复用
